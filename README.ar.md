# Engineering Coach — مدرّب الهندسة البرمجية

[English](README.md)

افهم الميزات التي تنجزها بمساعدة الذكاء الاصطناعي، وتعلّم تشخيص أخطائها وتطويرها بنفسك. تحوّل هذه المهارة تغييرات حقيقية في الكود أو محادثة عن ميزة إلى درس هندسي مركّز.

مهارة واحدة بستة أوضاع، تعمل مع **Codex وClaude Code**. ملفات المهارة مكتوبة بصيغة Markdown ولا تحتاج إلى مكتبات تشغيل خاصة بها. يوفّر مساعد البرمجة النموذج والأدوات، وتظل متطلبات الحساب وحدود الاستخدام المعتادة سارية.

## بداية سريعة

ثبّت المهارة باتباع التعليمات أدناه، ثم أعطها تغييرًا حقيقيًا:

```text
Codex:       $engineering-coach changes <PR, commit, diff, file, or chat reference>
Claude Code: /engineering-coach changes <PR, commit, diff, or file>
```

مثال: «اشرح المشكلة، وتتبّع قيمة تكشف الخطأ في الكود القديم والجديد، وبيّن كيف أتعرف على مشكلة مشابهة لاحقًا».

## أوضاع التعلّم الستة

| الوضع | ما تتعلّمه | مثال تكتبه بعد اسم المهارة |
| --- | --- | --- |
| `changes` | ما الذي تغيّر وكيف يعمل الإصلاح أو الميزة | `changes اشرح هذا التغيير قبل الإصلاح وبعده` |
| `decisions` | القرارات والبدائل والمفاضلات وحدود الاختيار | `decisions لماذا جمعنا قراءات قاعدة البيانات؟` |
| `terms` | المصطلحات المرتبطة بالكود بأمثلة واضحة | `terms اشرح RMS وthreshold وhysteresis هنا` |
| `flow` | مسار طلب أو حدث عبر البيانات والحالة | `flow تتبّع إطارًا صوتيًا عبر هذا المرشّح` |
| `quiz` | فحص الفهم بأسئلة توقّع وتشخيص وتعليل | `quiz اختبرني في هذا الإصلاح بسؤال واحد كل مرة` |
| `practice` | تمرين صغير لتطبيق الفكرة بمعايير نجاح واضحة | `practice أعطني تمرينًا مشابهًا لمشكلة تجميع القراءات` |

الكلمات بعد اسم المهارة تختار وضعًا داخلها؛ ليست ستة أوامر مستقلة. يمكنك أيضًا الطلب بلغة طبيعية. إذا قدّمت تغييرًا دون تحديد الوضع، يكون الافتراضي `changes`. وإذا لم يوجد طلب واضح أو مادة محددة، تعرض المهارة قائمة مختصرة للاختيار.

أوضاع الشرح تجيب أولًا، ثم تعرض سؤال فهم قصيرًا. أما الاختبار والتمرين فينتظران محاولتك، ويقدّمان تلميحات عند طلبها، ثم يشرحان الإجابة. يمكنك دائمًا القول: **«أعطني الإجابة»** أو **«بدون أسئلة»** أو **«اشرح بتفصيل أكبر»** أو **«اشرح بالعربية»**.

## التثبيت

استنسخ المستودع العام في مكان تختاره:

```sh
git clone https://github.com/MohammedNoureldeen/engineering-coach.git
cd engineering-coach
```

انسخ مجلد `skills/engineering-coach` **كاملًا**، بما فيه `references` و`agents`. اختر موقع تثبيت واحدًا لكل أداة حتى لا تُكتشف نسخ مكررة.

| الأداة | مجلد المستخدم المقصود | الاستدعاء |
| --- | --- | --- |
| Codex | `~/.agents/skills/engineering-coach` | `$engineering-coach changes ...` |
| Claude Code | `~/.claude/skills/engineering-coach` | `/engineering-coach changes ...` |

### Windows PowerShell

شغّل الأوامر من داخل المستودع المستنسخ. المثال التالي يثبّت المهارة لـCodex:

```powershell
$coachSource = (Resolve-Path '.\skills\engineering-coach').Path
$coachDestination = Join-Path $HOME '.agents\skills\engineering-coach'
if (Test-Path -LiteralPath $coachDestination) { throw 'Skill already exists; see Updating.' }
New-Item -ItemType Directory -Force -Path (Split-Path -Parent $coachDestination) | Out-Null
Copy-Item -LiteralPath $coachSource -Destination $coachDestination -Recurse
```

للتثبيت في Claude Code، استخدم `'.claude\skills\engineering-coach'` في سطر الوجهة بدلًا من مسار `.agents`. وللتثبيت في الأداتين، شغّل المجموعة مرة لكل وجهة.

### macOS / Linux

شغّل الأوامر من داخل المستودع المستنسخ. المثال التالي لـCodex:

```sh
coach_destination="$HOME/.agents/skills/engineering-coach"
if [ -e "$coach_destination" ]; then
  echo "Skill already exists; see Updating."
else
  mkdir -p "$(dirname "$coach_destination")" &&
    cp -R skills/engineering-coach "$coach_destination"
fi
```

لـClaude Code، استخدم `coach_destination="$HOME/.claude/skills/engineering-coach"`. وللتثبيت في الأداتين، كرّر المجموعة لكل وجهة.

ابدأ جلسة جديدة بعد التثبيت. ينبغي أن يكتشف Codex المهارة باسم `engineering-coach` وأن يظهر `/engineering-coach` في Claude Code. إذا لم تظهر، تأكد أن `SKILL.md` موجود مباشرة داخل مجلد الوجهة، وأن التثبيت تم في البيئة نفسها التي تعمل فيها الأداة. قد تختلف مجلدات المستخدم بين Windows وWSL.

إذا كان تثبيت Codex لديك يستخدم المسار القائم `$CODEX_HOME/skills`، يمكنك استخدامه بدلًا من `.agents/skills`. لا تثبّت المهارة نفسها في الموقعين. راجع [توثيق Codex](https://learn.chatgpt.com/docs/build-skills) و[توثيق Claude Code](https://code.claude.com/docs/en/skills) لسلوك الاكتشاف الخاص بكل أداة. بيانات العرض الخاصة بـCodex موجودة في `agents/openai.yaml`، وتعليمات التعليم مشتركة بين الأداتين.

### التحديث

شغّل `git pull --ff-only` داخل نسختك من المستودع. انقل مجلد `engineering-coach` المثبّت إلى نسخة احتياطية **خارج مجلد مهارات الأداة**، ثم كرّر خطوات النسخ. إبقاء النسخة الاحتياطية خارج هذا المجلد يمنع اكتشافها كمهارة مكررة، والنسخ إلى وجهة فارغة يمنع بقاء ملفات قديمة. احتفظ بتعديلاتك الشخصية في النسخة الاحتياطية وأعد تطبيق ما تحتاجه منها بعناية.

### الإزالة

احذف مجلد `engineering-coach` المثبّت فقط من الوجهة التي اخترتها، ثم ابدأ جلسة جديدة. إذا ثبّتّه للأداتين فاحذف النسختين. نسخة المستودع منفصلة ويمكن الاحتفاظ بها لاستخدامها لاحقًا. لا يلزم تعديل الإعدادات العامة أو المهارات الأخرى.

## التعلّم من محادثة أخرى

إذا كانت الأداة تدعم الإشارة إلى المحادثات أو ربطها وتوفّر وسيلة لقراءتها، أرفق محادثة الميزة واطلب:

```text
$engineering-coach changes
اشرح الميزة من المحادثة المشار إليها، وافحص التغييرات الفعلية إن كانت متاحة.
```

وجود عنوان أو إشارة لا يعني تلقائيًا إمكانية القراءة. تستخدم المهارة أدوات القراءة المتاحة؛ وإذا تعذّر الوصول، الصق الجزء المهم من المحادثة أو وفّر فرق الكود أو الملفات ذات الصلة. تثبيت المهارة في Claude Code لا يمنحه وصولًا إلى محادثاتك في Codex أو ChatGPT.

الملف الحالي يكفي لشرح السلوك الحالي. أما المقارنة بين الماضي والحاضر فتحتاج إلى نسختين أو فرق فعلي. تُراجع ادعاءات المحادثة السابقة في ضوء الكود عندما يكون متاحًا، ويُذكر نقص الأدلة بوضوح.

## جرّب الأمثلة التعليمية

هذه أمثلة مصطنعة للتعلّم، ولا تحتوي على مواد من مشاريع خاصة:

- [خطأ عند حد انتهاء الصلاحية](examples/bug-fix.md): قارن السلوك عند الحد نفسه وافهم اختبار الإصلاح.
- [قراءات قاعدة البيانات من نوع N+1](examples/n-plus-one.md): ناقش عدد الرحلات والسجلات المفقودة وحدود التجميع.
- [بوابة ضوضاء صوتية](examples/noise-gate.md): تتبّع الحالة وافهم المصطلحات وحدود الترشيح بالعتبات.

من داخل المستودع، جرّب `$engineering-coach decisions examples/n-plus-one.md` أو `/engineering-coach terms examples/noise-gate.md`. تحتاج الأداتان إلى إمكانية قراءة ملفات الأمثلة. وللشرح بالعربية: `$engineering-coach changes examples/bug-fix.md اشرح بالعربية`.

## طريقة التعليم

تجمع الحلقة التعليمية بين شرح ملموس واسترجاع قصير وتطبيق الفكرة على حالة جديدة. يتغيّر العمق حسب أسئلتك وفهمك الظاهر. تستند المهارة إلى ما فحصته، وتوضح متى يكون التعليل استنتاجًا؛ ولا تختلق قياسات أداء أو تدّعي تنفيذ اختبارات كانت مجرد اقتراحات.

الوضع الافتراضي للتعليم هو القراءة فقط. تظهر التمارين في المحادثة، ويتطلب تنفيذها أو تعديل الملفات طلبًا منفصلًا منك. يبقى التعلّم داخل المحادثة ما لم تطلب حفظه. لا توجد خدمة لتتبّع المتعلّمين أو نظام تذكيرات.

يوجّه ملف [SKILL.md](skills/engineering-coach/SKILL.md) إلى دليل كل وضع عند الحاجة. النسخة الإنجليزية من التعليمات هي المرجع الأساسي للسلوك، وتأتي الردود بلغة المستخدم مع المصطلحات الإنجليزية بجانب الشرح العربي عند فائدتها.

اطّلع على [الأساس البحثي](docs/learning-design.md)، و[نتائج التحقق وحدوده](docs/validation.md)، و[دليل المساهمة](CONTRIBUTING.md). توثيق التوافق مع Claude Code منفصل عن التحقق الفعلي أثناء التشغيل. المشروع متاح وفق [رخصة MIT](LICENSE).
