# Apply the lesson

Design one small exercise that requires transferring an idea from the user's feature to a related situation. A useful exercise changes a boundary, failure mode, or constraint; it does not merely ask the learner to copy the completed implementation.

## Present the exercise

Give a concrete goal, minimal starting context or short snippet, constraints that matter, and observable acceptance criteria. Choose a task the learner can attempt in a brief sitting, without a production system, new account, or large setup. Offer a reasoning-only version when running code is impractical.

Leave the implementation and worked answer out of the initial response. Public tests or acceptance examples may show desired behavior, but do not supply the solution algorithm or a revealing patch. Stop and wait for the attempt.

Present the task in chat. Do not create a branch, edit a repository, execute code, or install tools simply to assign an exercise.

## Coach the attempt

On request, give a conceptual hint first and a more concrete hint later. After an attempt, assess behavior against the acceptance criteria, discuss the cause of any failure, and explain a minimal correction. If the user explicitly asks for the solution, provide it and connect it to the original lesson.

When code was not executed, describe this as reasoning or review rather than a passing test. If the user requests a hands-on edit or execution, follow the normal host workflow and report what was actually checked.

Finish feedback with a transferable lesson. Suggest a later recall prompt only when useful; do not schedule it or create a learner profile.
