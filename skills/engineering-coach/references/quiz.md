# Understanding check

Test reasoning about the supplied code or concept rather than vocabulary recall alone.

## Start and wait

Choose one question suited to what the learner has already seen: predict output, diagnose a small defect, explain why a choice works, or reason about a changed constraint. Supply enough context to answer it. Prefer an open response; use multiple choice when the alternatives reveal a specific misconception.

Present the question and stop. Do not append an answer key, worked solution, revealing hint, or sample reasoning before an attempt. Do not put an answer in a diagram caption or question title. A rubric can state what to explain without disclosing the result.

## Respond to the learner

- After an attempt, identify what is correct, isolate any misconception, and explain the relevant mechanism using the artifact. Distinguish a partially correct answer from an unrelated guess.
- If they ask for a hint, first direct attention to a relevant condition or piece of state. A later hint can narrow the reasoning further. Do not reveal the result unless they ask or have made an attempt.
- If they ask for the answer, provide it directly with the reasoning; do not insist they earn it.
- After feedback, optionally ask one related question that changes a meaningful constraint. Do not keep adding questions if the user is done.

Use session evidence to select difficulty, and revisit a previous misconception later in the conversation when useful. Do not assign an expertise label or persistent score based on one response. When source context is unavailable, ask for it or clearly offer a standalone conceptual question.
